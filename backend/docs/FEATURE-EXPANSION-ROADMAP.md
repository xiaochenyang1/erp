# ERP 功能扩展路线图

## 总原则

- 历史单据保持现有本位币语义，不回填虚构汇率。
- 新功能必须包含迁移、权限、API、前端入口、自动化测试和 smoke 验收。
- 每个阶段独立提交，不能把多个领域混成一个发布提交。

## 阶段一：多币种基础

### 目标

支持公司/账套本位币、币种主数据、汇率有效期和新单据原币/本位币金额。

### 兼容规则

- 历史单据的币种默认为账套本位币。
- 新增币种字段允许为空，读取时按本位币解释，避免破坏旧接口和旧数据。
- 汇率在单据保存或提交时快照，不随之后的汇率修改而改变历史单据金额。
- 财务报表默认按本位币汇总，原币明细另行展示。

### 实现顺序

1. `md_currency`、`md_exchange_rate` 和账套本位币配置。
2. 币种/汇率维护 API、权限和前端配置页。
3. 统一金额换算服务和汇率有效性校验。
4. 采购、销售、收付款、发票、合同逐模块接入。
5. 汇兑损益和报表口径。

## 后续阶段

1. 固定资产：资产卡片、折旧、转移、处置和总账关联。
2. 税务基础：税码、税率、进销项税额和税务报表。
3. 供应商协同与客户门户。
4. 售后、维修和设备管理。
5. 高级生产排程。
6. 自助 BI 分析。

## 当前不纳入第一阶段

税局接口、集团合并报表、完整 SaaS 租户运营、移动端、自由 BPM 和复杂 APS。
