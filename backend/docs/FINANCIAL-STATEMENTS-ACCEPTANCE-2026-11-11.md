# 财务报表二期预生产验收清单（2026-11-11）

## 适用范围

本清单用于 `feature/phase2-financial-statements` 合并前后的真实账套验收，覆盖 V175 试算平衡、资产负债表和利润表，以及 V176 直接法现金流量表。当前实现是管理报表最小版，不是完整法定报表格式，也不包含间接法现金流量表。

自动化 API/UI smoke 只提供技术证据。财务负责人必须使用最终候选 SHA、独立预生产账套、真实或脱敏期初余额与凭证逐项复核。

## 前置条件

- [ ] 同一候选 SHA 的后端全量测试、MySQL 8.4/Testcontainers、前端门禁、31 路由/43 工作流 UI smoke 和部署验证全部通过。
- [ ] V175、V176 在目标数据库按顺序执行且仅执行一次，`flyway_schema_history` 无失败记录。
- [ ] 账套已有经确认的科目、期初余额和开放会计期间；测试凭证不会污染生产数据。
- [ ] 已准备凭证录入、过账、报表查看、科目映射和无权限账号，职责分离符合上线方案。
- [ ] 已约定报表日期、预期金额、舍入规则、导出归档位置和异常处置负责人。

## 验收项目

| ID | 场景 | 通过标准 | 实测/证据 | 通过 |
|---|---|---|---|---|
| FS-1 | 在生产备份副本或等价账套执行 V175、V176 升级 | 两个迁移各执行一次；模板、账套映射和既有凭证完整；升级可重复启动且无脏迁移 | | ☐ |
| FS-2 | 选定期间查询试算平衡，并与总账抽样核对 | 期初 + 本期发生 = 期末；借贷发生额及期末借贷合计平衡；异常反向余额按实际净额展示 | | ☐ |
| FS-3 | 查询报告日资产负债表 | 项目取数与科目映射一致；资产总计 = 负债和权益总计；未平差额明确展示并阻止“已核对”结论 | | ☐ |
| FS-4 | 查询利润表并与权益侧累计利润核对 | 收入、费用、净利润与期间凭证一致；累计净利润与资产负债表权益侧公式勾稽 | | ☐ |
| FS-5 | 过账一组现金收付并查询直接法现金流量表 | 经营/投资/筹资分类正确；期初现金 + 本期净现金流量 = 期末现金 | | ☐ |
| FS-6 | 现金或现金等价物科目之间内部转账 | 转出与转入不计入现金流量项目，现金净增加额为零 | | ☐ |
| FS-7 | 对已入账现金业务执行红冲/反向凭证 | 原现金流量被等额抵销，分类和勾稽关系保持正确，不重复计入 | | ☐ |
| FS-8 | 新增或启用有余额/发生额但未映射的科目 | 报表列出未映射科目及配置错误，核对状态失败；完成映射后错误消失且金额进入正确项目 | | ☐ |
| FS-9 | 分别使用有、无会计科目管理权限的账号维护映射 | 有权限账号可维护合法映射；无权限账号被拒；重复、类别不匹配、失效科目和不存在项目不能保存 | | ☐ |
| FS-10 | 导出试算平衡、资产负债表、利润表和现金流量表 CSV | 日期、金额、口径版本、核对状态及未映射/配置错误与页面一致；失败报表不被包装成已核对文件 | | ☐ |
| FS-11 | 两个账套配置不同映射并查询同一日期 | 模板可共用，但科目映射、现金范围、凭证和报表结果严格按账套隔离，无跨账套读写 | | ☐ |
| FS-12 | 与财务负责人确认产品边界 | 签字记录明确当前是管理报表最小版、现金流量表仅直接法，不将其描述为完整法定格式或间接法报表 | | ☐ |

## 必须归档的证据

- 最终候选完整 SHA、CI URL、JAR/前端制品/SBOM 的 SHA-256。
- V175、V176 的 `flyway_schema_history`、升级前后备份信息和目标 MySQL 版本。
- 31 路由、43 工作流 UI smoke 原始报告及财务报表 API smoke JSON。
- FS-1–FS-12 对应的凭证号、科目余额、页面截图、四类 CSV、权限拒绝记录和配置变更审计。
- 财务负责人对科目映射、报表口径、管理报表边界和未完成项的书面确认。

## GO / NO-GO

以下条件同时满足才可把财务报表二期判定为 GO：

- FS-1–FS-12 全部通过并绑定同一最终候选 SHA；
- 没有未关闭的报表金额、账套隔离、权限或迁移 P0/P1 缺陷；
- 未映射科目和配置错误已清零，四类 CSV 与页面及总账抽样一致；
- 已明确记录管理报表、直接法和非法定格式边界；
- 数据库及附件备份可恢复，候选具备可执行的回退方案。
