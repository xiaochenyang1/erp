# 财务三大报表二期设计

## 目标与发布边界

财务报表作为二期能力在独立分支开发，不进入尚未完成真实预生产、人工签字和正式发布的一期候选。

实施顺序固定为：

1. 统一试算平衡口径；
2. 建立报表项目、科目映射和公式版本；
3. 实现资产负债表；
4. 实现利润表；
5. 完成勾稽测试和导出；
6. 最后实现现金流量表。

## 第一期切片：试算平衡

查询按当前 `company_id + account_book_id` 隔离，日期区间为闭区间：

- 期初余额：`biz_date < dateFrom` 的累计借贷净额；
- 本期发生：`dateFrom <= biz_date <= dateTo` 的借方、贷方发生额；
- 期末余额：期初净额 + 本期借方 - 本期贷方；
- 净额大于等于零显示在借方余额，小于零显示在贷方余额；
- 金额统一保留两位小数。

返回科目类别与余额方向，但试算平衡的借贷列按实际净额展示，不强行把异常反向余额改回科目默认方向。

必须同时给出期初、本期、期末三组借贷合计及平衡标志。任何一组借贷差额不为零都属于需要调查的数据异常，后续正式财务报表不得把异常静默吞掉。

## 资产负债表与利润表

V175 使用显式版本 `TYPE_MAPPING_V1`，新增全局报表项目模板和账套级科目映射：

- `ASSET` → 资产；
- `LIABILITY` → 负债；
- `EQUITY` → 所有者权益；
- `REVENUE` / `EXPENSE` → 利润表，并以累计净利润公式补入资产负债表权益侧。

报表计算只读取已进入账簿的凭证分录，并复用试算平衡引擎：

- 资产负债表取截至报告日的期末余额；
- 利润表取报告期间的收入、费用净发生额；
- 未映射且有余额/发生额的科目必须进入校验结果并阻止“已核对”状态；
- 资产总额必须等于负债与权益合计；
- 本期损益必须与权益变动勾稽。

`TYPE_MAPPING_V1` 是管理报表最小版，不冒充法定报表格式。报表引擎按 V175 配置聚合科目，不再在代码里按科目类别动态生成项目。新增科目必须由具备会计科目管理权限的人员显式映射；重复映射、类别不匹配、失效科目或未映射且有余额/发生额都会进入校验结果。

试算平衡、资产负债表和利润表均提供 CSV 导出。导出文件携带口径版本、核对状态及未映射/配置错误信息，禁止把校验失败的导出物当成已核对报表。

验证包括 H2 全量 Flyway、MySQL V175 直接执行、租户表覆盖、服务与权限测试，以及前端类型、lint 和交互测试。当前本机 MySQL 9.7 从空库执行全部历史迁移时会在既有 V121 约束名上停止，因此本轮只能证明 V175 自身在真实 MySQL 上可执行；完整 V1→V175 链路仍由 MySQL 8.4 Testcontainers/CI 复验。

## 现金流量表

V176 实现直接法主表，公式版本为 `CASH_FLOW_DIRECT_V1`。现金流量表不从科目类型直接猜测业务分类，而是使用账套级配置：

- `sys_cash_flow_item_template` 保存经营、投资、筹资三类报表项目；
- `fin_cash_equivalent_subject` 保存现金及现金等价物科目范围；
- `fin_cash_flow_subject_map` 将非现金对方科目唯一映射到现金流量项目；
- 默认账套只将 `1002` 纳入现金范围，其他账套和新增科目必须显式维护。

计算按包含现金科目的完整凭证分组：

- 凭证现金净额为现金分录的 `借方 - 贷方`；
- 现金净额为零时视为现金账户内部转账，不进入主表；
- 非现金分录按 `贷方 - 借方` 贡献到其映射项目，因此收款为正、付款为负；
- 多行凭证按各对方科目分别归类，红冲凭证按借贷反向自然抵销；
- 使用本位币账簿分录，不把原币金额混入主表。

报表必须满足 `期初现金 + 本期现金净增加额 = 期末现金`。未映射且有现金影响的对方科目、重复映射、失效科目、现金科目误作对方科目或勾稽差额不为零，都会阻止“已核对”状态。查询结果和 CSV 均携带公式版本、勾稽差额及校验明细。

当前迭代只交付直接法主表；从净利润出发的间接法调节表留待后续版本，不能用当前直接法结果冒充间接法附表。
