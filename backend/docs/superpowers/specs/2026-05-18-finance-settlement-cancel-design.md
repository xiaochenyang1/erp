# 收付款作废最小闭环设计

## 背景

当前后端已经支持收款单、付款单创建、核销和查询，`fin_receipt`、`fin_payment` 表状态也已经预留了 `CANCELLED`。但接口和服务层没有真正打通作废动作，导致一旦录错收付款，只能改数据库或者人工兜底，这种做法很快就会把账搞脏。

这次目标不是上复杂红冲体系，而是在现有轻量财务模型上补齐最小纠错闭环：允许已过账收款单、付款单执行作废，自动回退对应核销金额，保留作废审计信息。

## 目标

- 为收款单、付款单增加正式作废接口。
- 作废时回退对应应收、应付的 `settled_amount` 和结算状态。
- 在业务表中记录作废原因、作废人、作废时间。
- 保持接口幂等，避免重复作废造成金额二次回退。
- 不引入红冲单、反向单或新的复杂财务模型。

## 非目标

- 不做 `reverse` 红冲单。
- 不做新的核销事件表或独立作废记录表。
- 不删除原核销明细行。
- 不补前端页面。
- 不修改现有收付款创建和列表查询口径。

## 方案选择

采用“状态作废 + 金额回退 + 审计落表”的平衡方案。

- 已过账收款单、付款单允许执行 `cancel`。
- 作废后单据状态改为 `CANCELLED`。
- 原核销明细保留，作为历史事实。
- 系统根据核销明细反向扣减对应应收、应付的已核销金额。
- 作废原因、作废人、作废时间直接记录在收付款头表。

这样做的重点是把纠错限制在当前轻量模型里，不发明新单据，也不让会计事实彻底丢失。

## API 设计

新增接口：

- `POST /api/finance/payments/{id}/cancel`
- `POST /api/finance/receipts/{id}/cancel`

请求体统一为：

```json
{
  "reason": "录入金额错误"
}
```

规则：

- `reason` 去首尾空格后不能为空。
- `reason` 长度不超过 200 个字符。
- 只有 `POSTED` 状态允许执行首次作废。
- 已经是 `CANCELLED` 时按幂等返回当前详情，不再重复回退金额。

响应继续复用现有详情 DTO，并新增作废字段：

- `cancelReason`
- `cancelledBy`
- `cancelledTime`

## 数据模型

在 `fin_payment` 新增：

- `cancel_reason VARCHAR(255)`
- `cancelled_by BIGINT`
- `cancelled_time TIMESTAMP`

在 `fin_receipt` 新增：

- `cancel_reason VARCHAR(255)`
- `cancelled_by BIGINT`
- `cancelled_time TIMESTAMP`

同步扩展：

- `PaymentResponse`
- `ReceiptResponse`

不新增新表，不改现有核销明细表结构。

## 事务流程

### 付款单作废

1. 按当前公司加载付款单。
2. 若单据不存在、已删除或跨公司，返回“付款单不存在”。
3. 若状态为 `CANCELLED`，直接返回当前详情。
4. 若状态不是 `POSTED`，返回“只有已过账付款单可以作废”。
5. 查询该付款单全部核销明细。
6. 对每条核销明细加载对应应付记录并校验：
   - 应付存在、未删除、同公司。
   - 当前 `settled_amount >= allocation.amount`。
7. 逐条回退应付已核销金额：
   - `settled_amount = settled_amount - allocation.amount`
   - 重新计算 `UNSETTLED / PARTIALLY_SETTLED / SETTLED`
8. 更新付款单：
   - `status = CANCELLED`
   - `cancelReason / cancelledBy / cancelledTime`
   - 常规更新审计字段
9. 返回最新详情。

### 收款单作废

流程完全对称，只是回退对象从应付改成应收。

## 业务规则

- 作废只允许一次，后续重复请求必须幂等。
- 原核销明细保留，不做物理删除，也不改金额。
- 作废后单据不允许再次参与任何新业务动作。
- 作废只回退当前单据自己占用的核销金额，不影响其他收付款单。
- 如果作废前发现关联应收、应付金额已经被人为改坏，直接拒绝作废，不做“猜着修”。

## 异常与冲突处理

建议错误口径：

- 付款单不存在 / 收款单不存在
- 只有已过账付款单可以作废
- 只有已过账收款单可以作废
- 作废原因不能为空
- 作废原因长度不能超过 200 个字符
- 应付记录不存在
- 应收记录不存在
- 应付已核销金额不足，无法作废当前付款单
- 应收已核销金额不足，无法作废当前收款单
- 相关记录已被其他操作修改，请刷新后重试

并发控制继续沿用现有乐观锁保护。

## 上线注意事项

- 这是业务纠错动作，不是会计红冲，后续如果财务需要正式反向凭证，再单独开设计。
- 现有报表若按 `POSTED` 过滤收付款，需要确认作废后是否自动排除。
- 前端后续联调时，详情页和列表页应显式展示 `CANCELLED` 状态及作废原因，别把已作废单据装成正常单。
