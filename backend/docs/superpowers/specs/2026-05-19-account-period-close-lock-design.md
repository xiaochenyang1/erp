# 库存财务对账与期间锁账设计

## 背景

当前后端已经具备采购、销售、库存、轻量财务、凭证分录、总账明细账、期初数据导入和最小自动化回归。系统已经能形成库存与财务事实，但还没有库存财务对账、会计期间和锁账能力。

这意味着用户可以在历史月份继续过账、作废、红冲或提交期初导入。账能跑起来是一回事，账能不能被稳定封存是另一回事。没有锁账，报表今天对、明天飘，这种 ERP 上线后会非常难查。

当前还有一个更具体的口径缺口：库存流水已经记录 `inv_txn.amount`，财务凭证分录已经记录 `fin_voucher_entry`，但销售出库只生成应收和收入凭证，没有结转库存成本。这样库存金额减少了，`1001 库存商品` 财务科目不减少，库存财务对账天然不平。要做月结锁账，先得把这口径补上，不然等于拿歪尺子量房子。

本设计补齐第一版库存财务对账、销售出库成本结转、会计期间、月结检查和业务日期锁账。目标是先保护已经形成的库存与财务事实，不在本阶段扩展完整财务结账体系。

## 目标

- 提供按账簿和月份管理的会计期间。
- 支持生成年度期间、查询期间、锁定期间、关闭期间、最近期间反打开。
- 提供库存财务对账查询，按期间比较库存流水净额与 `1001 库存商品` 科目净额。
- 对账结果能列出差异来源：库存有流水但无库存凭证、凭证有库存科目但无库存流水、金额不一致。
- 补齐销售出库成本结转凭证，让库存出库成本同步贷记 `1001 库存商品`。
- 锁定或关闭期间前执行强制月结检查，检查失败不允许进入下一状态。
- 对所有会改变库存或财务事实的业务动作做业务日期锁账校验。
- 提供结构化月结检查结果，方便前端展示和人工处理。
- 保持现有草稿、查询、报表、导出和主数据维护不受锁账影响。

## 非目标

- 不做成本重算。
- 不做月末库存快照。
- 不做库存成本重估和历史成本重算。
- 不做税务结转。
- 不做损益结转。
- 不自动生成结转凭证。
- 不支持任意历史期间反打开。
- 不支持库存期间和财务期间分开锁。
- 不做对账结果持久化快照，第一版实时查询。
- 不回填历史销售出库成本凭证。
- 不把锁账逻辑下沉到数据库触发器。

## 方案选择

采用“中心化期间服务 + 显式业务入口校验”。

新增 `finance/period` 模块，作为会计期间、对账和锁账的唯一业务入口。业务模块在执行会改变库存或财务事实的动作前，显式调用 `AccountPeriodGuard.requireOpen(bizDate, action)`。期间模块只判断业务日期能不能写事实，不替采购、销售、库存、财务、导入模块处理各自业务规则。

这个方案比数据库触发器更容易测试和排错，也比只拦财务凭证生成更完整。锁账能力必须覆盖事实源头，否则财务锁了、库存和业务单据还在历史期间乱改，账照样会飘。

第一版采用库存和财务同期间锁定，不拆库存期间和财务期间。原因很简单：现有系统的库存流水、财务凭证和业务单据在一个账套内形成闭环，拆开锁会立刻引出“库存已结、财务未结还能不能补凭证”这类问题。当前阶段先做一个硬朗的共同锁账口径，后续确实需要分层期间时再演进。

## 数据模型

新增迁移建议命名为 `V40__finance_account_period_reconciliation_schema.sql`。

### `fin_account_period`

- `id`
- `company_id`
- `account_book_id`
- `period_year`
- `period_month`
- `start_date`
- `end_date`
- `status`: `OPEN`、`LOCKED` 或 `CLOSED`
- `locked_by`
- `locked_time`
- `closed_by`
- `closed_time`
- `reopened_by`
- `reopened_time`
- `remark`
- `created_by`
- `created_time`
- `updated_by`
- `updated_time`
- `version`

约束与索引：

- `company_id + account_book_id + period_month` 唯一。
- 按 `company_id + account_book_id + status + period_month` 建索引。
- `period_month` 使用 `YYYY-MM` 字符串或等价的年月字段；服务层仍以 `LocalDate` 判断日期落点。

状态含义：

- `OPEN`：允许写入该期间库存和财务事实。
- `LOCKED`：禁止写入该期间库存和财务事实，允许对账、查询、导出和反打开。
- `CLOSED`：最终关账状态，禁止写入，也禁止反打开。

第一版不新增对账结果表。库存财务对账实时从 `inv_txn` 和 `fin_voucher_entry` 汇总，避免把一个还在演进的口径提前固化成快照表。

## 模块设计

### `AccountPeriodService`

职责：

- 生成某一年 12 个月期间，已存在的月份跳过或返回已有记录。
- 查询期间列表，支持按年份筛选。
- 查询业务日期所属期间。
- 锁定期间。
- 关闭期间。
- 反打开最近一个已锁定期间。

锁定期间时必须重新执行月结检查，不能依赖前端先调过 `close-check` 的结果。前端检查只用于展示，真正锁定必须二次校验。

关闭期间只允许从 `LOCKED` 进入 `CLOSED`。关闭不再反打开，作为最终关账确认。

### `AccountPeriodGuard`

职责：

- 提供 `requireOpen(LocalDate bizDate, String action)`。
- 使用当前用户的 `companyId` 和 `accountBookId` 查找业务日期所属期间。
- 未生成期间时拒绝写入，避免业务事实落到“无期间”的黑洞里。
- 期间已锁定或已关闭时拒绝写入，并返回明确错误。

建议错误信息：

```text
业务日期 2026-05-18 所属期间 2026-05 已锁定，不能执行采购入库过账
```

### `AccountPeriodCloseChecker`

职责：

- 执行锁定前检查。
- 返回结构化检查结果。
- 任一阻断项失败时，`lock` 拒绝锁定。

检查结果结构建议包含：

- `passed`
- `periodId`
- `periodMonth`
- `issues`

每个 issue 包含：

- `type`
- `severity`
- `bizType`
- `bizId`
- `bizNo`
- `message`
- `detail`
- `suggestion`

### `InventoryFinanceReconciliationService`

职责：

- 按公司、账套、期间汇总库存流水净额。
- 按公司、账套、期间汇总 `1001 库存商品` 科目借贷净额。
- 返回期间级对账摘要和来源差异明细。
- 支持按仓库、商品、业务类型、单号筛选差异明细。

第一版对账口径：

- 库存净额：`inv_txn.direction = IN` 记正，`OUT` 记负，按 `occurred_time` 落期间。
- 财务库存净额：`fin_voucher_entry.subject_code = '1001'`，借方记正，贷方记负，按 `biz_date` 落期间。
- 差异金额：`inventoryNetAmount - financeInventoryNetAmount`。

差异类型：

- `INVENTORY_WITHOUT_FINANCE`：库存流水找不到对应库存商品凭证分录。
- `FINANCE_WITHOUT_INVENTORY`：库存商品凭证分录找不到对应库存流水。
- `AMOUNT_MISMATCH`：两边能按来源匹配，但金额不一致。

来源匹配优先使用 `bizType/sourceType + bizNo/sourceNo`，同一来源多行时以来源汇总金额比较，避免库存按商品明细多行、财务凭证按科目汇总导致误报。

### `SalesCostPostingService`

职责：

- 销售出库过账时，使用库存出库成本金额生成成本结转凭证或补充分录。
- 销售退货过账时，按退货入库金额生成反向成本结转凭证或补充分录。
- 幂等处理同一来源单据，避免重复生成成本分录。

成本结转科目：

- 销售出库：借 `6402 主营业务成本`，贷 `1001 库存商品`。
- 销售退货：借 `1001 库存商品`，贷 `6402 主营业务成本`。

本设计建议新增默认科目 `6402 主营业务成本`。不回填历史销售出库成本凭证，历史差异由对账报表暴露并交给人工处理。

## API 设计

新增控制器：`AccountPeriodController`。

- `GET /api/finance/periods`
  - 查询期间列表。
  - 支持 `year` 参数。
  - 权限：`finance:period:view`。

- `POST /api/finance/periods/generate`
  - 生成某一年 12 个月期间。
  - 请求体包含 `year`。
  - 权限：`finance:period:manage`。

- `GET /api/finance/periods/{id}/close-check`
  - 只执行月结检查，不修改期间状态。
  - 权限：`finance:period:close`。

- `GET /api/finance/periods/{id}/reconciliation`
  - 查询库存财务对账摘要。
  - 权限：`finance:period:view`。

- `GET /api/finance/periods/{id}/reconciliation/differences`
  - 查询库存财务对账差异明细。
  - 权限：`finance:period:view`。

- `POST /api/finance/periods/{id}/lock`
  - 重新执行月结检查和库存财务对账，全部通过后锁定期间。
  - 权限：`finance:period:close`。

- `POST /api/finance/periods/{id}/close`
  - 只允许锁定期间进入最终关闭状态。
  - 权限：`finance:period:close`。

- `POST /api/finance/periods/{id}/reopen`
  - 只允许反打开最近一个已锁定期间。
  - 权限：`finance:period:reopen`。

新增权限码：

- `finance:period:view`
- `finance:period:manage`
- `finance:period:close`
- `finance:period:reopen`

## 锁账覆盖范围

第一版只拦截会改变库存或财务事实的动作。

### 采购

- 采购入库过账。
- 采购退货过账。

业务日期：入库单或退货单业务日期。

### 销售

- 销售出库过账。
- 销售退货过账。

业务日期：出库单或退货单业务日期。

### 库存

- 库存调整生效或过账。
- 盘点差异生效。
- 库存调拨过账。
- 库存预留释放或修复，如果会改变库存可用事实，也要校验。

业务日期：对应库存业务单据日期。没有独立业务日期的动作使用服务生成库存流水的业务日期。

### 财务

- 收款单创建。
- 付款单创建。
- 收款单作废。
- 付款单作废。
- 费用过账。
- 费用红冲。

业务日期：原收款单、付款单或费用单日期。作废和红冲按原业务事实日期判断，不按当前操作日期判断。

### 期初导入

- 期初库存提交。
- 期初应收提交。
- 期初应付提交。
- 期初科目余额提交。

业务日期：导入行内业务日期或生成凭证的业务日期。

### 不拦截范围

- 草稿创建和草稿编辑。
- 查询、报表和导出。
- 主数据维护。
- 审批记录写入本身，除非审批动作同时触发业务过账。

## 月结前强制检查

锁定某个月份前，任何阻断项失败都不允许锁定。

### 库存财务对账检查

- 期间内库存净额必须等于 `1001 库存商品` 科目净额。
- 存在 `INVENTORY_WITHOUT_FINANCE`、`FINANCE_WITHOUT_INVENTORY` 或 `AMOUNT_MISMATCH` 差异时，视为失败。
- 销售出库成本凭证缺失会表现为库存出库有流水、财务库存科目无贷方分录，必须修复后才能锁定。

### 凭证平衡检查

- 期间内所有 `POSTED` 凭证的分录借贷必须相等。
- 存在凭证头但没有分录，视为失败。

### 导入任务检查

- 存在 `VALIDATED`、`COMMITTING`、`FAILED` 的期初导入任务，视为失败。
- `INVALID` 只表示历史预览错误，不阻止关账。

### 收付款核销检查

- 期间内未作废收款单的 `allocatedAmount` 必须等于核销明细合计。
- 期间内未作废付款单的 `allocatedAmount` 必须等于核销明细合计。

### 应收应付金额检查

- `settledAmount` 不能小于 0。
- `settledAmount` 不能大于 `originalAmount`。
- `status` 必须和剩余金额匹配：未核销、部分核销、已核销。

### 库存余额检查

- 当前库存余额数量不能为负。
- 当前库存余额金额不能为负。

第一版只检查当前余额，不做历史月末快照。

## 锁定、关闭与反打开规则

锁定规则：

- 只能锁定 `OPEN` 状态期间。
- 锁定前必须执行月结检查和库存财务对账。
- 检查失败时返回结构化 issue，不修改期间状态。
- 锁定成功后记录 `lockedBy` 和 `lockedTime`。

关闭规则：

- 只能关闭 `LOCKED` 状态期间。
- 关闭成功后记录 `closedBy` 和 `closedTime`。
- `CLOSED` 为最终状态，不允许反打开。

反打开规则：

- 只能反打开 `LOCKED` 状态期间。
- 只能反打开当前账簿最近一个已锁定期间。
- 反打开成功后状态回到 `OPEN`。
- 记录 `reopenedBy` 和 `reopenedTime`。
- 不支持打开任意历史期间。

如果要打开更早月份，必须先逐月反打开后续锁定期间。这个限制不花哨，但能防止历史月份被随便撬开，账务风险会小很多。

## 数据流

1. 管理员生成 2026 年期间。
2. 日常业务照常创建草稿、审批、查询。
3. 执行过账、作废、红冲、期初提交时，业务服务调用 `AccountPeriodGuard.requireOpen(bizDate, action)`。
4. 月末管理员先调用 `close-check` 和 `reconciliation` 查看问题。
5. 修复问题后调用 `lock`，服务重新检查并锁定期间。
6. 锁定后若确认无误，可调用 `close` 进入最终关闭状态。
7. 如果锁错，只允许对最近已锁定期间执行 `reopen`。
8. 反打开后，对应期间恢复业务事实写入能力。

## 错误处理

- 未生成期间：拒绝写入，提示先生成会计期间。
- 已锁定或已关闭期间：拒绝写入，提示业务日期和动作名。
- 月结检查失败：返回所有阻断 issue，不只返回第一条。
- 重复锁定或重复关闭：返回业务错误，不静默成功。
- 非最近锁定期间反打开：返回业务错误。
- 并发更新期间状态：沿用乐观锁冲突错误。

## 测试计划

新增最小自动化测试覆盖：

- 生成年度期间，重复生成不创建重复月份。
- 锁定 `OPEN` 期间成功写入锁定审计字段。
- 月结检查失败时不能锁定期间。
- 关闭 `LOCKED` 期间成功写入关闭审计字段。
- `CLOSED` 期间不能反打开。
- 只能反打开最近已锁定期间。
- 锁定期间后，代表性事实写入口被拦截：
  - 采购入库过账。
  - 销售出库过账。
  - 库存调整过账。
  - 付款单创建或作废。
  - 收款单创建或作废。
  - 费用过账或红冲。
  - 期初导入提交。
- 月结检查能发现：
  - 库存财务对账差异。
  - 凭证借贷不平。
  - 凭证头无分录。
  - 期初导入存在未完成状态。
  - 收付款核销金额不一致。
  - 应收应付金额或状态不一致。
  - 库存余额负数。
- 销售出库能生成成本结转分录：借 `6402`，贷 `1001`。
- 销售退货能生成反向成本结转分录：借 `1001`，贷 `6402`。
- 库存财务对账能发现：
  - 库存流水缺少库存商品分录。
  - 库存商品分录缺少库存流水。
  - 同来源金额不一致。
- `scripts/release-check.ps1` 必须通过。

## 上线注意事项

- 上线前需要先为当前账簿生成覆盖现有业务数据日期范围的期间。
- 如果历史业务数据已经存在，第一轮锁定通常会暴露旧数据口径问题，应先修数据或修规则，不要直接改期间状态硬锁。
- 本设计不回填历史销售出库成本凭证，历史期间对账差异属于预期风险，需要人工确认后处理。
- 锁定期间后，历史业务事实写入会被拒绝；前端应在对应页面展示清晰错误信息。
- 反打开权限必须只给少数财务管理员。
- 本功能不替代预生产人工验收，尤其是采购到付款、销售到收款和总账明细账核对。
