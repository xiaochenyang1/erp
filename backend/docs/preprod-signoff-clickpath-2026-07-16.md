## 一、财务 F1–F12

### F1 / F2 — 费用过账与红冲

| | |
|--|--|
| **样例** | `FE202607150005` |
| **菜单** | 财务管理 → **费用管理** → `/finance/expenses` |
| **操作** | 搜索费用单号 `FE202607150005` → 打开详情 |
| **看什么 F1** | 状态 `POSTED`；能看到过账凭证号；打开凭证分录借贷合计相等、科目合理 |
| **看什么 F2** | 存在红冲/冲销关联凭证；原凭证与红冲金额相反、净额可解释为 0 |
| **证据备选** | `target/ui-smoke-report.json` workflow `finance-expense-create-submit-approve-post-reverse` |

### F3 / F4 — 手工凭证

| | |
|--|--|
| **样例** | `MV202607150003` |
| **菜单** | 财务管理 → **手工凭证** → `/finance/vouchers/manual` |
| **操作** | 搜索 `MV202607150003` → 详情 |
| **看什么 F3** | 状态曾过账；凭证查询 `/finance/vouchers` 或总账/明细账 `/finance/ledger` 能查到对应分录 |
| **看什么 F4** | 作废后有红冲凭证；总账净额归零（可按科目+期间汇总目视） |
| **证据备选** | ui-smoke `manual-voucher-create-submit-approve-post-cancel` |

### F5 — 销售发货生成应收

| | |
|--|--|
| **样例** | 发货 `SD202607160004`；应收 `AR-SALES_DELIVERY-2077598953381076994` |
| **菜单** | 销售管理 → **销售发货** → `/sales/deliveries` |
| **操作** | 搜 `SD202607160004` → 状态 **已过账 POSTED**；金额（含税）记下 |
| **再去** | 财务管理 → **应收管理** → `/finance/receivables` 搜来源发货或客户 |
| **通过标准** | 应收金额 = 发货含税金额；来源类型销售发货 |

### F6 — 收款核销应收 SETTLED

| | |
|--|--|
| **样例** | 收款 `FR202607160004`；应收同上 |
| **菜单** | 财务管理 → **收付款管理** → `/finance/payments`（收款 Tab） |
| **操作** | 搜 `FR202607160004` → 状态 **POSTED**；核销金额 20（或与发货一致） |
| **再去** | `/finance/receivables` 看对应应收 **SETTLED / 剩余 0** |
| **关联销售** | 订单 `SO202607160004` → `/sales/orders` |

### F7 — 销售退货应收冲减

| | |
|--|--|
| **样例** | 退货 `SRT202607150005`；发货 `SD202607150016` |

| **再去** | `/finance/receivables` 查该客户/发货是否有 **DECREASE/OFFSET** 冲减记录 |
| **库存可选** | 库存查询 `/inventory/stocks` 看对应商品可用量回升 |

### F8 — 采购入库应付 + 付款核销

| | |
|--|--|

### F9 — 采购退货应付冲减

| | |
|--|--|

### F10 — 期间边界（需人工点负例）

| | |
|--|--|
| **样例期间** | `2026-07` 当前为 **OPEN**（正向已通过） |
| **菜单** | 财务管理 → **会计期间** → `/finance/periods` |
| **正向** | 确认 2026-07 状态 OPEN；业务日 2026-07-16 可过账（已由本包证明） |
| **负例（建议）** | ① 选一已过账单据改到**无期间/锁定期间**日期尝试过账应失败；或 ② 对测试期间执行锁定后再过账应拒绝 |
| **通过标准** | 开放期间可过；锁定/关闭期间拒绝并有明确提示 |
| **说明** | 本机为了验收全年 OPEN，**不要**在共享联调库上乱锁生产期；可用新建测试年期间做负例 |

## 二、质检 Q1–Q5

### Q1 — 需检商品可建 IQC

| | |
|--|--|
| **样例** | 检验 `QC202607150003`；入库 `PR202607150013` |
| **菜单** | 质量管理 → **来料检验** → `/qc/inspections` |
| **操作** | 搜 `QC202607150003`；关联入库 `PR202607150013` |
| **可选** | 主数据 → 产品 → 确认商品 `inspectionRequired` 为需检 |
| **通过** | 草稿入库可生成检验单 |

### Q2 — 判定后 JUDGED 与数量

| | |
|--|--|
| **菜单** | `/qc/inspections` → 详情 `QC202607150003` |
| **通过** | 状态 **已判定 JUDGED**；合格+不合格=检验数量；合格/不合格数与业务预期一致（smoke 曾用合格 3 / 不合格 1 类口径） |

### Q3 — 仅合格品回写入库数量

| | |
|--|--|
| **菜单** | 采购收货 `/purchase/receipts` → `PR202607150013` |
| **通过** | 入库单行数量被回写为**合格数量**（小于原报检数量时更明显） |
| **对照** | 检验单详情合格数量 = 入库行数量 |

### Q4 — 未判定过账闸门（建议现点）

| | |
|--|--|
| **准备** | 新建需检商品 + 采购订单审批 + **草稿入库** + **未判定/未通过** 的 IQC（或根本不建 IQC，视闸门配置） |
| **操作** | 对草稿入库点 **过账** |
| **通过** | 被拒绝，提示需质检/未判定类信息 |
| **说明** | 历史 smoke 数据可能已 JUDGED，需**新造一单**负例；admin 有权限时勿绕过业务规则误过账 |

### Q5 — 作废与权限

| | |
|--|--|
| **作废** | `/qc/inspections` 找 DRAFT/SUBMITTED → 作废 → 不可再判定 |
| **编辑权限** | DRAFT 有「编辑」按钮（`qc:inspection:update`）；改日期/行数量保存成功 |
| **权限** | 用无 `qc:inspection:*` 角色登录时按钮应隐藏（与 F11 同法） |

## 四、故障排查

| 现象 | 处理 |
|------|------|
| 侧边栏没有财务/质检 | 确认用 admin；菜单种子是否到 V104；`GET /api/system/menus/tree` |
| 搜不到单号 | 确认库是 `erp_codex_runtime`；日期筛选清空；直接贴完整单号 |
| 登录 429 | local 已关 rate-limit；若仍 429 重启后端 jar |
| 前端空白 | Vite 5173 是否起；代理是否指 8080 |
