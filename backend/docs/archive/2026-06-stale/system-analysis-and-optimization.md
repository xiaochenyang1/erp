## ⚠️ 发现的问题与优化建议

### 🔴 高优先级问题（需要立即处理）

#### 1. 字段命名不一致（已部分修复）
**问题描述**:
- 前后端字段命名规范不统一
- 产品：`productCode` vs `code`
- 客户：`customerCode` vs `code`
- 供应商：`supplierCode` vs `code`

**影响范围**: 所有业务模块

**解决方案**:
- ✅ 已修复：主数据4个模块
- ⚠️ 待修复：采购、销售、库存、财务模块

**优化建议**:
```
方案A（推荐）：前端统一适配后端字段名
方案B：后端重构字段名（影响大，不推荐）
方案C：制定统一规范，新模块遵循
```

---

#### 2. 分页响应格式不统一
**问题描述**:
- 后端返回：`{records, total, pageNo, pageSize}`
- 前端期望：`{content, totalElements, number, size}`

**当前状态**: 主数据模块已通过映射适配

**优化建议**:
- 统一使用后端格式
- 更新所有页面组件的类型定义
- 创建统一的分页响应包装器

---

#### 3. 缺少统一的错误处理
**问题描述**:
- 前端错误处理不统一
- 有的用`try-catch`，有的直接调用
- 错误提示不够友好

**优化建议**:
```typescript
// 创建统一的错误处理函数
export const handleApiError = (error: any, defaultMsg: string) => {
  const msg = error?.response?.data?.message || defaultMsg
  ElMessage.error(msg)
  console.error(error)
}
```

---

#### 4. 缺少加载状态管理
**问题描述**:
- 按钮点击后没有loading状态
- 可能导致重复提交
- 用户体验不佳

**优化建议**:
- 提交按钮添加loading状态
- 表单添加防重复提交
- 全局loading统一管理

---

### 🟡 中优先级问题（建议优化）

#### 5. 缺少数据验证
**问题**: 前端表单验证不完整，后端缺少统一参数校验

**优化建议**:
- 前端：完善所有表单验证规则
- 后端：使用@Valid和@Validated
- 统一错误返回格式

#### 6. 缺少数据缓存
**问题**: 字典数据、用户信息每次都请求，影响性能

**优化建议**:
- Pinia持久化缓存
- 字典数据本地缓存
- Redis缓存热点数据

#### 7. 缺少操作确认
**问题**: 提交、审批等重要操作缺少确认

**优化建议**:
- 重要操作添加二次确认
- 使用已封装的确认对话框

#### 8. 缺少批量操作
**问题**: 只能单条操作，效率低

**优化建议**:
- 批量删除
- 批量导入
- 批量状态修改

```typescript
request.interceptors.request.use(config => {
  // 添加loading

})

// 响应拦截
request.interceptors.response.use(
  response => response.data.data,
  error => {
    handleApiError(error)
    return Promise.reject(error)
  }
)
```

#### 2. 全局状态管理
```typescript
// 字典数据缓存
export const useDictStore = defineStore('dict', {
  state: () => ({ dicts: {} }),
  actions: {
    async loadDict(type: string) {
      if (!this.dicts[type]) {
        this.dicts[type] = await getDictData(type)
      }
      return this.dicts[type]
    }
  },
  persist: true
})
```
