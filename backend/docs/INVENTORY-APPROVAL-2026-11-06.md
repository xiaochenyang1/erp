# 库存调整审批开发记录（2026-11-06）

本次按首发优先级修复生产依赖漏洞，并补齐原 V1 要求的库存调整审批。本地开发与验证基于 `8766ef0ac966da8628bbdfc2b9bbb12c6e93ba17` 的工作树完成；最终候选以相应提交的 CI 和部署验证结果为准。

## 已完成的业务行为

- 库存调整必须经过 `DRAFT → SUBMITTED → APPROVED → POSTED`。提交和审批不写库存流水、余额或财务凭证；所有审批节点完成后才允许过账。
- 支持驳回、修改后重提，以及提交人在审批尚未处理时撤回。禁止自审，沿用审批配置中的节点、审批人、ANY/ALL、通知及审计记录。
- 审批中心可以处理库存调整。通用审批权限不能绕过库存审批权限，公司、账套和仓库数据范围校验仍然生效。
- 审批记录展示历次提交、驳回、撤回和通过，重提不会隐藏先前记录。
- 盘点操作生成关联调整草稿，盘点状态变为 `ADJUSTMENT_PENDING`（待调整过账）；关联调整审批通过并成功过账后，盘点才变为 `ADJUSTED`。
- 待调整的盘点不能直接编辑或取消。取消尚未过账的关联调整后，盘点恢复 `COUNTED`，数据库中的关联编号和 ID 清空，可修正盘点后重新生成。
- 盘点生成的调整单不能单独修改，以免与盘点数量脱节。两个页面可以相互跳转到对应单据。
- 过账仍执行附件、期间、库存及批次/序列号等既有校验。关联盘点状态冲突会回滚库存、凭证和调整状态。

## 升级与权限

[V169](../src/main/resources/db/migration/V169__inventory_adjustment_approval.sql)追加状态约束和默认审批配置，保留历史已过账调整及已调整盘点，不回写历史审批事实。原有未过账草稿升级后也必须先审批。

| 操作 | 所需业务权限 | 可操作状态 |
|---|---|---|
| 编辑 | `inventory:adjustment:update`（新增） | 手工调整的 DRAFT、REJECTED |
| 提交 / 撤回 | `inventory:adjustment:submit`（新增） | 提交：DRAFT、REJECTED；撤回：SUBMITTED 且符合提交人及未处理条件 |
| 通过 / 驳回 | `inventory:adjustment:approve`（新增） | SUBMITTED，且为当前节点可处理人 |
| 过账 | `inventory:adjustment:post` | APPROVED |
| 取消 | `inventory:adjustment:cancel` | DRAFT、REJECTED、APPROVED |

迁移按角色业务编码为现有 ERP_ADMIN 分配三个新增权限，并在尚无库存审批配置的对应账套建立一个 ANY 审批节点。已有自定义配置不被覆盖。其他业务角色需分配相应权限，并在“审批配置 → 库存调整”中设置实际审批人；提交人与审批人必须是不同账号。

审批中心的通过、驳回、撤回接口还要求对应的 `workflow:*` 权限。盘点生成接口继续使用 `POST /api/inventory/checks/{id}/adjust`，但现在返回待调整状态，不再自动过账。调用方已同步调整。
