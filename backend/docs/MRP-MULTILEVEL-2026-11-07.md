# 多层、分仓 MRP

MRP 按“商品 + 需求仓库”汇总需求和供应，再按 BOM 拓扑顺序计算净需求。自制半成品继续展开，外购商品停止展开。建议可以查看原始计算依据并生成采购订单或生产工单。

## 算法与数量口径

| 项目 | 口径 |
|---|---|
| 销售需求 | 已审批、未完全交付的销售行，数量为 `max(qty - delivered_qty, 0)`，使用销售单仓库 |
| 安全库存 | 每个商品、仓库的期末目标；历史重复规则取最高目标，不叠加 |
| 已有工单材料 | 已下达、已领料工单的 `max(required_qty - issued_qty, 0)`，使用工单投料仓 |
| 现存量 | 同商品同仓的 `qty_on_hand`；销售及生产材料需求已包含相应预占，不再重复扣减预占 |
| 采购在途 | SUBMITTED / APPROVED / PARTIAL 采购单的未收货数量，使用预计收货仓 |
| 生产在制 | RELEASED / MATERIAL_ISSUED 工单的未完工数量，使用成品仓 |
| 已转计划供给 | 由 MRP 转成、仍为 DRAFT 的采购单或生产工单；普通草稿不计入 |

已转生产草稿的未领材料同时计入需求。转单来源用 `EXISTS` 判断，单据即使出现多个历史关联也只计一次。已审批采购、已下达工单只计正常在途/在制，不再叠加草稿供给；作废单据释放相应供给。

每个节点只抵扣一次：

```text
净需求 = max(汇总需求 - 现存量 - 采购在途 - 生产在制 - 已转计划供给, 0)
材料需求 = 上层净生产数量 × BOM用量 / BOM基准数量 × (1 + 损耗率)
```

中间除法保留 8 位，结果按库存数量规则保留 4 位，HALF_UP，与生产工单材料快照相同。所有上层需求先合并，避免遍历顺序影响共享半成品和共用材料。最多支持 100 层、20,000 个商品仓库节点；越界、循环、失效引用、非法用量和多个启用 BOM 均中止运行。

验收算例：A 需求 10，A 每件用 B 2，B 每件用 C 3；B 现存 4、C 现存 10。结果为生产 A 10、生产 B 16、采购 C 38。浏览器用安全库存目标形成精确的 10A 根需求，并在另一个仓库放入 B/C 各 100，验证不会跨仓抵扣。销售单来源另由 HTTP 集成回归验证；现有销售审批执行库存预占。

## 配置与页面

- 商品表单增加 `mrpPolicy`：AUTO（有启用 BOM 则自制）、PURCHASE（外购）、PRODUCTION（自制，必须有唯一启用 BOM）。默认投料仓为空时使用当前需求仓；可配置成品与材料分仓。
- 旧客户端不传 `mrpPolicy` 时保留配置；显式传对象、投料仓为空或省略时清除投料仓配置。
- 采购订单增加 `plannedWarehouseId`。草稿表单可设置；详情页或 MRP 警告列表可给已提交、已审批订单单独设置收货仓，不改审批状态、价格和数量。
- 历史在途采购缺少仓库时，不猜测目标仓。相关商品参与本次计划就显示订单、商品和未收数量；补仓后重新运行才能转单。
- MRP 的仓库筛选只筛选展示；每次计算覆盖整个当前账套。建议显示需求仓、层级和已转单据。
- “计算依据”显示需求来源、供应来源和计算公式，可沿 BOM 来源逐层回到销售行、安全库存规则或生产工单。全部计算明细包含净需求为零的节点。
- 采购转单选择供应商；生产转单沿用计算时的成品仓、投料仓及 BOM。生成草稿后继续走各单据的正常审批、下达和收发流程。采购收货表单预填计划收货仓。

## 一致性与权限

运行与转单先锁定当前公司、账套的 MRP 编号规则行，写事务使用 REPEATABLE_READ。不同应用实例、不同运行同时转同一缺口时串行复算，第二次看到第一张草稿的供给，不会重复下单。同一行保留乐观锁，订单创建、行状态和计划状态在同一事务中提交。

转单前复算当前缺口，检查数量、库存、供应、供给类型、仓库、BOM 版本及材料组成。计算依据变化返回 409，提示重新运行；不会静默更改已保存建议数量。采购草稿和生产草稿可按任意顺序转换，已有工单材料与计划展开不会重复形成需求。

所有查询和引用均限定公司、账套。完整计划及其来源要求用户具有“全部数据范围”，避免从岗位或个人订单子集计算错误需求，或通过快照越权查看全账套来源。

| 操作 | 权限 |
|---|---|
| 查看计划/历史 | `inventory:mrp:view` |
| 运行计划 | `inventory:mrp:run` |
| 转采购 | `inventory:mrp:convert` + `purchase:order:create` |
| 转生产 | `inventory:mrp:convert` + `production:order:create` |
| 配置商品策略 | `masterdata:product:update`（新增用 create） |
| 设置采购收货仓 | `purchase:order:update`，并满足该采购单的数据范围 |

## 接口与历史兼容

现有 MRP 运行、历史、明细、转单路径保持不变。新增响应字段：

- 运行：`algorithmVersion = 2`、`calculationSnapshot`（全部节点、来源、警告）。
- 建议行：`warehouseId`、`materialWarehouseId`、`bomVersion`、`bomLevel`、`trace`。
- 商品：`mrpPolicy: { supplyType, materialWarehouseId }`。
- 采购单：`plannedWarehouseId`。
- `PUT /api/purchase/orders/{id}/planned-warehouse`，请求 `{ plannedWarehouseId }`。

V170 只增加列和索引，表数不变。历史运行保留 algorithm 1 和空仓库/快照，可查看，须重新计算后转单。不修改任何已发布迁移，也不回填虚构的仓库或来源。

升级演练的当前目标版本已随生产成本关单与差异结转迁移更新到 V173；V169 审批、V170 多层 MRP、V171 生产成本核算和 V172 冲销/更正的独立检查仍保留，V169/V170/V171/V172/V173 都必须且仅执行一次。回退要求恢复 V168 备份，确认没有任何高于 V168 的迁移。

## 自动化验证

- 纯引擎：10A→16B→38C、多父共用材料、直接与间接需求合并、分仓、自制/外购、循环、无效 BOM、基准数量和损耗、零缺口来源。
- 实际输入 SQL：采购部分收货、生产部分完工及未领料、普通/已转草稿、重复来源关联、失效状态、公司与账套隔离、缺仓警告。
- HTTP 工作流：保存和回读快照、任意顺序转单、重跑不重复、跨运行过时计划、仓库与 BOM 变化、采购补仓、商品配置的保留和清除、权限及数据范围。
- 并发事务：两个运行竞争同一缺口，只生成一张采购订单。
- V169→V170：旧行和解释保留、无虚构快照、表数不变、重复启动无重复迁移。
- 前端：API 数量及长 ID、策略配置、采购仓库、权限和禁用转单、类型检查、lint、构建。
- 浏览器：安全库存 4 件转采购、多层分仓与逐层追溯、采购/生产转单后复算、历史在途采购补仓重算；保留计算依据和转单页面截图。

本阶段为数量计划。日期为运行时快照，尚不包含提前期倒排、产能排程或替代料分配。真实业务数据和预生产环境的验收与隔离自动化回归分开记录。
