# Flyway 迁移历史说明

本文档记录 `src/main/resources/db/migration` 中已知的 Flyway 版本号缺口。Flyway 允许版本号不连续，但生产发布审计需要能解释每个缺口，避免把“有意跳号”和“迁移脚本丢失”混在一起。

## 当前缺口

| 版本 | 状态 | 说明 |
|---|---|---|
| V21 | 保留未使用 | 早期业务阶段切换后没有落地对应迁移，后续版本从 V22 继续。该缺口不是缺失的已发布脚本。 |
| V51 | 保留未使用 | readiness 能力落地前预留过版本号，实际 schema 从 V52 开始。该缺口不是缺失的已发布脚本。 |
| V79 | 本地历史保留 | 本机默认库已有历史脏记录占用 V79；异常处理闭环中心从 V80 追加，避免复用可能已污染的版本号。 |

## 维护规则

- 新增迁移优先使用当前最大版本号的下一个连续版本。
- 如果确实需要跳号，必须在同一个变更中更新本文档，写清楚跳过原因。
- 已发布迁移禁止重命名、重排或复用缺口版本号；新修正只能追加新版本。
- V145 及以前的部分历史脚本仍使用 MySQL 已弃用的 `VALUES(column)` 写法；为避免已部署库 checksum 漂移，不回改这些脚本。V146 起必须使用行别名写法，构建测试会阻止再次引入旧语法。
- V156 新增 `sys_scheduler_lease`，为异常规则自动化提供单行全局租约。该表不含租户列，租约获取与释放均按 `lease_key` 和 `owner_token` 条件更新，避免多实例重复扫描以及旧实例误释放新租约。
- V164 补种 6061「财务费用-汇兑损益」科目，V165 给 `fin_receipt_allocation`/`fin_payment_allocation` 增加 `base_settled_amount` 与 `fx_gain_loss_amount`。两者连续追加、无跳号；V165 为纯 DDL，历史行保留 0 默认值，不回填虚构汇率。
- V166 新增 `fin_fx_revaluation`，记录期末未实现汇兑损益调汇。已过账行占用 `generation = 0`，撤销时把 generation 改为行 id，以便同一期间再次调汇。纯 DDL，无跳号。
- V167 为 `fin_fx_revaluation` 追加 `basis_hash` 与 `basis_json`，保存逐笔期末余额、币种和汇率依据。历史记录保留 NULL；其原币合计不足以证明计算依据相同，打开期间须撤销旧调汇后重算，月结也按此检查。该迁移不回填历史依据，不改原凭证或已关闭期间，纯 DDL、无跳号。
- V168 为收付款核销和汇兑损益过账保存不可变的业务与本位币快照，作为当前升级/回退演练的旧版检查点。V168 及以前的备份必须能够由旧版应用恢复读取；升级候选只能通过后续迁移追加结构。
- V169 为库存调整增加待审批、通过、驳回状态，为盘点增加待调整过账状态，并按业务编码补种编辑、提交、审批权限与默认审批节点。历史已过账调整和已调整盘点保持原状；未过账调整必须先审批。ERP_ADMIN 获得新权限，其他角色由管理员明确分配；审批人不能是提交人。连续追加，无跳号。
- 发布复核看到版本缺口时，先查本文档，再核对 `flyway_schema_history`。
- V170 为多层分仓 MRP 增加商品供给策略、默认投料仓、采购预计收货仓和计划计算快照。历史计划保留算法版本 1，仓库和来源为空，查看兼容、转单须重算。纯扩展列/索引，表数不变、无跳号；详见 [多层 MRP](MRP-MULTILEVEL-2026-11-07.md)。
- V171 增加生产人工/制造费用归集单、工单与完工/反完工成本组成快照，历史数据全额回填为材料成本；同时补充 2211/5101 科目、成本归集权限与流水号。详见 [生产成本核算 1.0](PRODUCTION-COST-ACCOUNTING-1.0.md)。
- V172 为生产成本归集单增加不可变冲销与更正关联链，允许负向冲销记录和 `REVERSED` 原单状态，补充独立冲销权限；反向凭证冲回 5001，原归集单与凭证不删除、不改写。
- V173 为已完工工单增加成本关单与反关单流水，按剩余成本差异在 5001 与新增 5102 之间结转；工单关单后禁止新增、冲销或更正成本以及反完工，反关单使用独立反向凭证恢复原差异。零差异仍保留关单流水，但不生成空凭证。
- V174 为工作中心增加每日容量与开工时间，为工单工序增加标准工时和排程快照，并补充产能排程权限与菜单。迁移只提供排程一期所需的数据结构和默认值，不回填虚构的历史排程结果；详见 [有限产能排程一期](FINITE-CAPACITY-SCHEDULING-2026-11-08.md)。
