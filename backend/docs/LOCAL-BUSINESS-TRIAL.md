# 本机采销与财务演示

完整部署包第一次启动后没有业务仓库和开放期间。`scripts/trial-business-acceptance.mjs` 为本机试用建立明确标注的演示数据，并通过实际 API 校验采购、入库、付款、销售、发货、收款和库存结余。它保留样例单据和受限录单账号，供用户在界面核对。

## 运行

使用干净、已提交的工具检出，Node.js 22 和 Docker。先按 [完整部署说明](FULLSTACK-DEPLOYMENT.md) 启动一个 `erp-preview-*` 项目，仅绑定 `http://127.0.0.1`。脚本必须接收原部署包清单的独立摘要；同时核验实际容器所属项目、配置路径、健康状态、端口、运行 JAR 摘要及页面版本标记。

```bash
node backend/scripts/trial-business-acceptance.mjs \
  --bundle /absolute/deployment-bundle \
  --expected-manifest-sha256 <独立交接记录中的部署清单摘要> \
  --project erp-preview-example \
  --date 2026-10-28 \
  --evidence /absolute/new/trial-evidence
```

脚本从包的私有 `.env` 读取管理员凭据，不在命令参数或输出中打印密码。每次新运行生成独立 `DEMO-*` 名称、仓库、商品、往来方、部门、角色及录单账号；不会改写既有用户、角色或业务主数据。若该年份尚无会计期间，则生成年度期间；若日期落在已有非开放期间，直接失败，不解锁或重开已有期间。

## 样例和核对

| 阶段 | 独立计算的预期 |
|---|---|
| 采购入库 | 10 件 × 10 元 = 100 元；库存 10 件 / 100 元，应付 100 元 |
| 第一次付款 | 付款 40 元，应付剩余 60 元 |
| 第二次付款 | 再付 60 元，应付 SETTLED，剩余 0 |
| 销售发货 | 4 件 × 15 元 = 60 元；库存结余 6 件 / 60 元，应收 60 元 |
| 第一次收款 | 收款 20 元，应收剩余 40 元 |
| 第二次收款 | 再收 40 元，应收 SETTLED，剩余 0 |

样例为 CNY、汇率 1、税率 0。数量、库存金额、可用数量、预占数量以及应收应付的原始 / 已结 / 剩余 / 本位币剩余逐项核验，不能仅凭 HTTP 200 通过。多币种、税务、退货、月结和制造继续使用各自专项验收。

录单角色仅有订单查看 / 创建 / 提交、相关主数据查看及库存查看权限，数据范围限定自己的单据和演示仓库。脚本验证该账号可以查看自己的订单和库存，审批订单、财务查询与用户管理返回 403。管理员负责本次审批、出入库和收付款。真实岗位权限由实施人员按业务职责另行配置。

## 证据和失败处理

- `report.json` 保存应用 / 部署 / 验证工具版本、通过检查及每个已确认创建对象的 ID。
- `HANDOFF.md` 提供样例单号和界面核对说明。
- `private-account.json` 保存演示录单账号密码，权限为 `0600`；证据目录为 `0700`。共享报告时排除该文件。
- 证据目录必须不存在，拒绝覆盖完成或部分失败的记录。每次新目录代表一套新样例，并非对已有单据重复过账。
- 写请求不自动重试。中途失败记录 `FAILED` 和 `activeStep`，保留已创建对象；如果请求结果不明确，按演示标记和操作日志核对后再处理。脚本不自动删除单据或补偿已核销资金。

这是本机合成样例和技术核验，不能代替真实主数据 / 期初导入、业务人员核对或财务质检签字，也不会写入发布 GO 决定。

## 自动部署回归

`deployment-smoke.mjs` 已调用同一采销脚本，在一次性完整部署中验证真实 API 契约和业务结余。它保存 `business-trial/report.json`，但删除临时密码和交互说明，并随父脚本清理数据库与账号。交付时应同时检查父报告的 `status=PASSED`、`cleanupPassed=true` 及采销检查结果，不能把仅辅助函数测试通过当作整条业务链通过。
